# 高併發情境題

## 實務上常見的高併發場景

### 1. **限流控制（Rate Limiting）**
**場景描述：**
- API 服務需要限制每個用戶的請求頻率
- 防止惡意攻擊和系統過載
- 例如：每秒最多 100 個請求

**挑戰：**
- 如何統計請求次數？
- 如何處理時間窗口滑動？
- 如何保證併發安全？

**技術要點：**
- 使用 `sync.Mutex` 或 `atomic` 保護計數器
- 使用 `time.Ticker` 重置計數
- 考慮使用 Redis 做分散式限流

---

### 2. **連接池管理（Connection Pool）**
**場景描述：**
- 數據庫連接有限，需要複用連接
- HTTP 客戶端連接池
- 避免頻繁建立/關閉連接

**挑戰：**
- 如何管理連接的生命週期？
- 如何處理連接超時？
- 如何優雅關閉連接池？

**技術要點：**
- Channel 作為連接池
- Context 控制超時
- WaitGroup 等待連接歸還

---

### 3. **任務隊列處理（Task Queue）**
**場景描述：**
- 大量任務需要異步處理
- 例如：發送郵件、圖片處理、數據導出
- 需要控制併發數量，避免系統過載

**挑戰：**
- 如何控制 worker 數量？
- 如何處理任務失敗重試？
- 如何保證任務不丟失？

**技術要點：**
- Worker Pool 模式（參考 `cmd/demo`）
- Channel 作為任務隊列
- Context 控制取消和超時

---

### 4. **快取更新（Cache Update）**
**場景描述：**
- 熱點數據需要快取
- 多個請求同時查詢，只有第一個去數據庫查詢
- 其他請求等待第一個查詢結果

**挑戰：**
- 如何避免緩存擊穿（Cache Penetration）？
- 如何處理併發查詢？
- 如何保證數據一致性？

**技術要點：**
- `sync.Once` 或 `sync.Mutex` 保護查詢
- Channel 用於等待結果
- Context 控制超時

---

### 5. **批量處理（Batch Processing）**
**場景描述：**
- 大量小任務需要批量處理
- 例如：批量發送通知、批量更新數據
- 需要累積一定數量或時間後才處理

**挑戰：**
- 如何累積任務？
- 如何觸發批量處理？
- 如何處理部分失敗？

**技術要點：**
- Channel 累積任務
- `time.Ticker` 定時觸發
- Context 控制關閉

---

### 6. **並行查詢聚合（Parallel Query Aggregation）**
**場景描述：**
- 需要從多個數據源查詢數據
- 然後聚合結果
- 例如：從多個 API 獲取數據後合併

**挑戰：**
- 如何並行查詢？
- 如何處理部分失敗？
- 如何設置超時？

**技術要點：**
- 多個 goroutine 並行查詢
- Channel 收集結果
- Context 統一超時控制
- `sync.WaitGroup` 等待完成

---

### 7. **訂閱發布模式（Pub/Sub）**
**場景描述：**
- 多個訂閱者監聽同一事件
- 事件發生時通知所有訂閱者
- 例如：系統通知、消息推送

**挑戰：**
- 如何管理訂閱者？
- 如何處理訂閱者離線？
- 如何保證消息不丟失？

**技術要點：**
- Channel 作為事件通道
- Map 管理訂閱者
- Context 處理取消訂閱

---

### 8. **計數器/統計（Counter/Statistics）**
**場景描述：**
- 高併發環境下的計數統計
- 例如：點擊量、訪問量、在線人數
- 需要保證計數準確

**挑戰：**
- 如何保證併發安全？
- 如何提高性能？
- 如何持久化？

**技術要點：**
- `atomic` 操作（無鎖）
- `sync.Mutex`（有鎖但更靈活）
- 定期批量寫入數據庫

---

### 9. **資源競爭控制（Resource Contention）**
**場景描述：**
- 多個 goroutine 競爭同一資源
- 需要保證互斥訪問
- 例如：文件寫入、配置更新

**挑戰：**
- 如何避免死鎖？
- 如何提高併發度？
- 如何處理超時？

**技術要點：**
- `sync.Mutex` / `sync.RWMutex`
- Channel 作為鎖
- Context 控制超時

---

### 10. **優雅降級（Graceful Degradation）**
**場景描述：**
- 系統負載過高時自動降級
- 例如：關閉非核心功能、返回緩存數據
- 保證核心功能可用

**挑戰：**
- 如何檢測系統負載？
- 如何實現降級策略？
- 如何恢復服務？

**技術要點：**
- 監控 goroutine 數量
- Context 傳遞降級標誌
- Channel 控制流量

---

## 面試常見問題

### 問題 1：如何實現一個併發安全的計數器？
**考察點：**
- `sync.Mutex` vs `atomic`
- 性能考量
- 併發安全

### 問題 2：如何實現一個帶超時的任務執行器？
**考察點：**
- Context 超時控制
- Goroutine 管理
- 資源清理

### 問題 3：如何實現一個限流器？
**考察點：**
- 時間窗口滑動
- 併發安全
- 性能優化

### 問題 4：如何實現一個 Worker Pool？
**考察點：**
- Channel 使用
- Goroutine 管理
- 優雅關閉

### 問題 5：如何避免緩存擊穿？
**考察點：**
- `sync.Once` 使用
- 併發控制
- 錯誤處理
